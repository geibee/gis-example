# 区域詳細の並べ替えと地図ペインの折りたたみ対応計画

## 概要

- 区域詳細は土地・建物・関係者を残し、`土地 → 建物 → 関係者` の順に並べ替える。
- 地図ペインの「レイヤ」と「選択地物」を、それぞれ独立して折りたたみ・展開できるようにする。
- 地物の選択ロジックや吹き出しは変更しない。

## 実装内容

- 「レイヤ」は初期状態を折りたたみ、「選択地物」は初期状態を展開とする。
- `MapSupportPane` に各セクションの開閉状態を独立したローカル状態として持たせる。
- 各セクションのヘッダーに、操作内容が分かるアクセシブル名とシェブロンを備えた開閉ボタンを設け、`aria-expanded` と `aria-controls` を設定する。
- `aria-controls` の参照先には安定した一意 ID を付け、折りたたみ時も DOM からアンマウントせず `hidden` で非表示にする。
- レイヤ更新ボタン、地物編集ボタンなど既存の操作は開閉ボタンから分離する。ヘッダー全体には開閉ハンドラを置かず、開閉ボタンだけで状態を変更することで、`stopPropagation` に依存せず既存操作から誤って開閉されない構造にする。
- 選択地物を編集中に折りたたんでも、選択内容・編集モード・入力中の属性値と GeoJSON を保持する。
- 開閉状態は画面内のローカル状態とし、ブラウザ再読み込みをまたぐ永続化は行わない。
- 区域詳細は `ZoneWorkspace` の DOM 順を変更し、「含まれる土地」「含まれる建物」の後に `ZonePartySummary` の「関係者」を配置する。CSS の `order` だけによる視覚上の並べ替えにはしない。
- API、OpenAPI、DB クエリ、地物選択処理は変更しない。

## 変更対象

- `apps/web/src/components/ZoneWorkspace.tsx`: 区域詳細の関連セクションを並べ替える。
- `apps/web/src/components/MapSupportPane.tsx`: 独立した開閉状態、開閉ボタン、制御対象を追加する。
- `apps/web/src/styles.css`: 開閉ヘッダー、シェブロン、非表示状態のスタイルを追加する。
- `apps/web/src/components/MapSupportPane.test.tsx`: 開閉、アクセシビリティ、編集状態保持、既存操作との非干渉を検証する。
- `apps/web/src/components/ZoneWorkspace.test.tsx`: 区域詳細内の見出し順を検証する。既存テストへ自然に追加できる場合は、そのテストファイルへ追加してもよい。

## Feedback System との互換性

- 通常のボタン操作だけで開閉し、document のクリック判定、capture-phase、右クリック処理には介入しない。
- `test/feedback-system-next-clean` 統合時は `data-feedback-map` と `registerFeedbackMap(map)`、および登録解除処理を維持する。
- フィードバック対象選択モードおよび右クリック投稿のイベント処理を変更しない。
- Feedback System は現行 `main` に未統合で、Web の自動統合ティアも未定義であるため、統合後のブランチ上で後述の手動スモークを実施する。

## テスト計画

- 初期状態でレイヤが閉じ、選択地物が開いていることを確認する。
- 両セクションを独立して開閉でき、各開閉ボタンの `aria-expanded` が状態と一致することを確認する。
- 各開閉ボタンの `aria-controls` が実在する一意な ID を参照し、制御対象が折りたたみ時も DOM に残って `hidden`、展開時は表示状態になることを確認する。
- 開閉ボタンをアクセシブル名で取得でき、キーボード操作でも開閉できることを確認する。
- レイヤ更新ボタンを押すと更新処理だけが呼ばれ、レイヤの開閉状態は変わらないことを確認する。
- 地物編集ボタンを押すと編集状態だけが変わり、選択地物の開閉状態は変わらないことを確認する。
- 選択地物の編集中に属性値と GeoJSON を変更し、折りたたんで再展開しても入力値と編集状態が保持されることを確認する。
- 区域詳細の `.object-detail` 内に検証範囲を限定し、「含まれる土地」→「含まれる建物」→「関係者」の見出しが DOM 上でこの順になることを、関係者サマリの取得結果に依存しない形で確認する。
- `npm --workspace apps/web run test`、`npm --workspace apps/web run typecheck`、`npm --workspace apps/web run build` を実行する。
- 最終ゲートとして `VERIFY_SCOPE=web bash scripts/verify.sh` を実行する。

## Feedback 統合後の手動スモーク

`test/feedback-system-next-clean` を統合した構成と Feedback System の実行に必要なランタイム設定を用意し、ブラウザで次を確認する。自動 E2E を追加できる場合は同じシナリオを置き換えてよい。

1. 「レイヤ」と「選択地物」をそれぞれ開閉しても、もう一方の状態が変わらない。
2. 地図上の地物をクリックすると従来どおり選択され、選択地物セクションを展開して内容を確認できる。
3. フィードバック対象選択モードで対象を選択でき、セクション開閉ボタンの操作が対象選択として誤認されない。
4. 地図上の右クリックから投稿 UI を開いて投稿でき、通常の地物クリックやセクション開閉が同時に発火しない。
5. 投稿に添付される地図情報とスクリーンショットが従来どおり取得される。
